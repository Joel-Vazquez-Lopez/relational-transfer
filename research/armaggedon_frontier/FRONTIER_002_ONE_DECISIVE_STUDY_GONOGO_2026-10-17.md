## A falsifiable claim hierarchy

**Claim 0 — causal influence on answer source.** Targeted intervention changes which **recipient-local** event supplies the correct role-specific participant, beyond identity, unrelated-state and neighboring-token shams.

**Claim 1 — event identity rather than order/index.** Under a human-valid permutation of source event order and independent remapping of arbitrary marker names, a *predeclared event-address hypothesis* predicts transfer by event identity/semantic cue, while the specified *ordinal-only rival* predicts transfer by event slot. Both policies receive the same context; the specific predicted target in each crossed cell must be frozen before the heldout read. Crucially, if the event-address theory has no defined transferable event identity across different articles, it is invalid to label cross-article first/second transfer “semantic event identity.”

**Claim 2 — separable event and role controls.** A patch hypothesized to alter event choice while holding role fixed redirects both roles to the corresponding new **recipient-local gold**; a distinct role-specific patch changes role while preserving event; the combined patch reaches the predicted crossed cell under appropriate baseline competence. This is strongest if it generalizes across relations and candidate sites are fixed before heldout.

**Mechanism ceiling:** A fully competent compound-key syntax/parser/copier may realize the same 2×2 behavior and even the same controlled interventions. Identify only **restricted algorithm classes/path dependencies** that have genuinely different predictions under identical access and intervention budgets. Do not name the result a unique semantic circuit unless those alternatives are experimentally eliminated. Earlier [Dai et al. EMNLP 2024](https://aclanthology.org/2024.emnlp-main.967/) already localized and causally edited binding-related index information; new work must precisely exceed that scope.

## Frozen-design skeleton — only to be finalized if gates pass

### A. Data gate, prior to any new outputs

- Human-original MAVEN-Arg (or distinct documented source) **TRAIN/DEV** documents not exposed by prior six-doc, 17-doc, marked-stress, initial-patch, fresh-patch or scoring-patch studies. Official hidden TEST untouched.
- Each eligible item: two **distinct** original gold events of the relevant shared event type with two comparable gold roles and **four uniquely identifiable recipient-local fillers**. Trigger, original document ID, entity mention/coref annotation, exact evidence span, source version/hash and rights logged. Do not silently map dissimilar ontology roles to generic Patient.
- Both events and both requested roles **must pass untreated Qwen7B native answering** under same coherent output contract (correct *full 4-cell square*) for mechanistic *conditional-on-competence* analysis. Record all pre-screened failures and selection fractions, and report target population conditioning. Competence selection and patch-site identification use a separate disjoint development split; **do not select hidden confirmation documents based on their patched outcome**.
- Human review of source, event referents, and all proposed order swaps, independently by two reviewers where possible; resolving anaphora, event chronology, discourse dependency or duplicated referents required. If swapping clauses changes meaning, don't use that item. Do not convert artificial rewrites into supposedly original human-annotated heldout events.
- Predeclare minimum number of **independent documents** and stop decision from feasible accepted human gold; no significance claims from tiny cherry-picked subsets. Exact N and available hardware/cost must be approved in #31.

### B. Cross *order*, *label*, and *role* without assuming their invariance

For each approved natural two-event item, define stable underlying occurrence identities `E1`, `E2` with fixed original gold. Construct, only when semantically independently approved:

- `O∈{E1-first, E2-first}`: order of complete clauses/sentences in visible passage.
- `L∈{A→E1, A→E2}`: assignment of arbitrary marker label `A` to event occurrence, **independently of O**; explicit marker identities must be detectable.
- `R∈{Agent, Patient}`: requested role, each asked separately under identical answer contract.
- If possible, one **content identity / semantic cue** contrast independently of slot and arbitrary letter; e.g. distinct immutable *event-specific* predicate+participant descriptors in a same-document counterfactual. Freeze the precise informativeness and no gold leakage.

The scientific critical separation is **not** just reversing the spelling of labels. It is a factorial design in which **event content identity, positional order, displayed marker, query role and prompt/answer format are not perfectly correlated**.

### C. Predicted output *by rival*, preregister at cell level

- **Ordinal/index donor rival (`OI`)**: targeted donor activation conveys a first/second occurrence address; in mismatched donor/recipient order/label cells, answer follows the corresponding **recipient ordinal slot**. A label-name remapping alone is not proof against it.
- **Restricted event-identity-address (`EI`)**: patch conveys a source-defined *semantic event identifier* supported by invariant content features and selects corresponding **recipient event identity** after a valid swap. **Do not assume** EI is defined across unrelated donor articles; explicitly say which information in the recipient identifies the source's event.
- **Query-aware compound-key copier (`CK`)**: uses event marker, syntactic predicates, participant types and/or local order to retrieve the correct participant. It can mimic EI or OI, depending on precisely permitted inputs and computation. Model a **strong** competence-matched comparator; if it predicts every cell, answer `NO SEPARATING WITNESS`, even if patches work.
- **Independent role routing (`FR`)**: separate role-conditioned retrieval policies may not track a single donor event under both roles once event cue/participant position is counterbalanced; match shared covariates to avoid spurious marginal error-correlation.
- **Answer-content / generic patch (`AC`)**: donor-name transplant, final-token copying and generic format/position disruptions must be ruled out with donor-local vs recipient-local name checks, site/strength-matched unrelated controls and unchanged-target preservation.

**Preflight requirement:** For each proposed heldout intervention cell, write a literal expected `recipient event ID × role → entity` for each rival. If `EI`, `OI`, and competent `CK` make the same answer predictions under the available intervention, **DO NOT RUN A NEW MODEL ON THE PREMISE OF IDENTIFYING THE MECHANISM**.

### D. Frozen hardware and patch controls

One pinned **open-weight Qwen7B** checkpoint that shows baseline full four-answer competence; exact tokenizer/chat template, decoding, prompt, weights SHA, layer/token/site/patch norm and donor/recipient selection established on non-holdout development only. Keep identity patch, neighboring token, same-position irrelevant cue, shuffled/cross-document donor, source-content-unchanged sham and equal-size/equal-norm replacement. Patches on native answer path; no auxiliary probe-as-proof. If hardware requires extra resource, user approval before downloading/running. Hosted Gemma provides only a separate behavioral competence comparator.

### E. Endpoints and disallowances

**Primary** heldout by-document count: full **correct recipient-local role-pair acquisition** for intervention-target event with specified `EI` vs `OI` vs `CK` predictions, including retention of unmodified event answers; report `wrong→correct`, `correct→wrong`, `wrong→wrong`, unchanged, invalid and ambiguous **against all attempted eligible documents**. Secondary: 4/4 square under role patch/crossed patch, intervention order, per-role logit margin, and negative-control specificity.

Cluster by **source document**. No single-answer success ≡ full shared-record success. No posthoc exclusion or changed scoring contract to rescue scoring-run failures. Freeze donor content, exact candidate layer/site and competitor predictions **before testing untouched documents**. Keep all failures.
