## Smallest defensible pretrained experiment, once data rights / cold replay and model identity accepted
1. **Primary task = original human QA-SRL dev question→multi-answer-span**, without coercing questions into universal binary actor/patient. Freeze `qasrl_id,verb_idx,question`, all accepted half-open spans, row provenance, original sentence/predicate identity, and reasoned inclusion/exclusions. Sentence/document/sample groups are dependent.
2. **Two genuinely distinct untouched model families**: candidates Qwen2.5-7B-Instruct and Phi-3-mini-4k-instruct (~3.8B), pending exact checkpoint, quantization, original prompt templates, local availability, license and source-model-use approval. Nova owns execution, not Comput.
3. **Development-only bounded sample**: 24–48 distinct predicate questions, spanning different source documents where verified, with explicit actor-like/non-actor question taxonomy *as post hoc descriptive grouping*, several multiple-answer and passive examples; exclude prior Astra 63 from novel benchmark claims, or tag separately as exposed development. Fix prompt and budget before seeing predictions; include source/predicate question and instruction to copy source-grounded answer spans; never show IDs/gold/worker metadata to models. Preflight 5–10 items separately and keep them excluded from primary pilot.
4. **Scoring**: match original human answer-span **set** (or official QA-SRL metric), zero-based half-open token ranges, normalize only prespecified typography; return exact-span and answer-validity metrics, coverage/abstention, stratify multi-span, question type, passive, source corpora and grouped source ID. Never count one of several gold spans as full multi-span correctness. Report doc-level paired differences with a small-n warning.
5. **Input-only controls**: exact question-language string extraction, first/last source person/NP, nearest candidate to anchored verb, voice/syntax rule, copying and answer frequency; prohibit gold-aware candidate construction. Include question-only and sentence-only conditions only if predeclared and interpretable; using a source-specific parser is a legitimate strong comparison.
6. **Safety/claims**: the real-language pilot is exploratory DEV, not semantic-mechanism evidence, not a confirmation of directed latent roles. Independently adjudicated new role labels/untouched different-document confirmation needed for stronger claims. No work assigned to user for local runs without a clear, bounded request.

**Decision:** Recommend Nova run a tiny two-family pilot only after **exact official DEV cold parsing/scoring, rights/model-processing approval, checkpoint identities and approved inference budget**. In parallel Comput can run source-only baseline scripts on permitted DEV text; no need to duplicate Nova's runner. Optional LLM silver annotation is separate developer aid, not reference gold.
